# Прототипирование энергетического VAD

## Зачем skill

Прошивка для кулона ещё не написана, а алгоритм VAD уже нужно тюнить и проверять.
Путь такой: синтетический аудио-файл с известной разметкой → настольный симулятор
того же алгоритма, что будет в прошивке → подбор констант → перенос в C как есть.

## Алгоритм (константы — единый источник истины: docs/vad_design.md)

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| Блок | 20 мс (320 сэмплов, 16 кГц mono int16) | = один Opus-фрейм |
| Метрика | средний модуль сэмпла → дБFS | не RMS: только abs и накопление |
| Пол шума | EMA, α=0.01/блок, обновлять ТОЛЬКО в тишине | иначе пол «вползает» в речь |
| Открытие | SNR > 10 дБ, 2 блока подряд | атака против щелчков |
| Закрытие | SNR < 5 дБ | гистерезис против дребезга |
| Hangover | 300 мс | иначе режутся затухания согласных |

## Рабочий цикл

1. Сгенерировать синтетику с ground truth:
   `python tools/gen_synth_audio.py synth.wav --labels synth.labels.json --dur 30 --seed 42`
   — в JSON лежат интервалы речи и истинный уровень шума.
2. Прогнать симулятор:
   `python tools/vad_sim.py synth.wav --labels synth.labels.json`
   — печатает оценённый пол шума, precision/recall/F1 по сегментам, смещения старта.
3. Тюнить параметры только флагами CLI (`--open-snr`, `--close-snr`, `--hangover-ms`),
   не редактируя генератор. Дефолты в симуляторе = дефолты дизайна.
4. Проверить устойчивость: перегенерировать с другим `--seed` и другим
   `--noise-floor-db` (тихая комната −55, улица −35) и убедиться, что F1 не падает.
   Порог в дБFS — плохой порог; SNR относительно оценённого пола — хороший.
5. Перенести в прошивку можно только константы и логику, не уровни:
   абсолютные дБFS на реальном микрофоне другие (см. «Аппаратное ограничение»).

## Подводные камни

- Пол шума должен обновляться только когда VAD «молчит»; обновление во время
  речи поднимает пол и гасит хвосты слов.
- Без hangover сегменты рвутся на слоги; без атаки (2 блока) — одиночные щелчки
  открывают ложные сегменты.
- В начале записи микрофон устаканивается ~0.5–1 с: первые 25 блоков (0.5 с) —
  фаза калибровки, пол шума сходится быстрой EMA (α=0.2), решения отключены.
  Без неё VAD открывается на первом блоке и уже не закрывается (поймано
  на синтетике: сегмент «0.02 … 30.00 с» при истинном поле −45 дБFS).
- Известный предел дизайна: если шум внезапно поднимется посреди «активного»
  сегмента (замороженный пол станет заниженным), сегмент не закроется.
  Страховка для прошивки: принудительное закрытие и пересчёт пола шума,
  если сегмент длится дольше ~30 с. В прототипе не реализовано — задокументировано.
- Симулятор и C-код должны давать одинаковые решения на одинаковых блоках;
  расхождение почти всегда — в порядке округления α или в float vs fixed.

## Проверка результатов

Приёмка: precision и recall по сегментам ≥ 0.9 на дефолтных параметрах,
смещение старта сегмента ≤ 40 мс (2 блока атаки), оценённый пол шума
в пределах ±3 дБ от истинного. Ниже — не тюнить параметры, а искать баг.
