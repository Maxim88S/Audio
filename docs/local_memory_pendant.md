# Local Memory Pendant — кулон-память разговоров без облака

> Идея устройства по итогам исследования аналогов Omi Pendant (см. [omi_pendant_alternatives.md](../omi_pendant_alternatives.md)).

## Суть

Носимый кулон, который постоянно (или по кнопке) записывает разговоры, но **ни при каких условиях не отправляет звук в чужое облако**. Записи хранятся в самом кулоне, а расшифровка делается на компьютере или домашнем мини-сервере пользователя. Интернет для работы не нужен вообще.

Ниша пустая: из всех исследованных устройств локальную обработку даёт только заброшенный проект Owl (2024). У Omi и всех коммерческих кулонов звук уходит в облако производителя. Риск показал Limitless: сервис купила Meta и отключила — пользователи лишились истории записей.

## Кому нужно

Людям, которым запись нужна, а отправка разговора в облако — недопустима:

- юристы и HR (оговорки NDA);
- врачи и психотерапевты;
- журналисты на встречах с источниками;
- инженеры и госслужащие под конфиденциальными контрактами;
- пользователи в регионах, где облачные сервисы блокируются.

## Схема

```
[MEMS I2S-микрофон]
      │
      ▼
[VAD (ESP-SR)] → [Opus-кодирование] → [кольцевой буфер PSRAM/SD, ~7 дней]
      ▲
[тумблер mic-off: физически рвёт линию микрофона + светодиод записи]

  синхронизация: USB-C или Wi-Fi (точка доступа) — по желанию пользователя
      │
      ▼
[домашний хаб: ПК / Raspberry Pi]
      │  faster-whisper (расшифровка) → опционально Ollama (саммари)
      ▼
[расшифровки и саммари — только на диске пользователя]
```

| Компонент | Откуда | Лицензия |
|---|---|---|
| Форм-фактор и схемотехника кулона | KiCad-файлы Omi ([BasedHardware/omi](https://github.com/BasedHardware/omi)) | MIT |
| Протокол Opus-over-GATT, кольцевой буфер | [cgallic/omi-pendant-chronicle](https://github.com/cgallic/omi-pendant-chronicle) | MIT |
| Каркас серверной части (STT → саммари) | [nytka-app/server](https://github.com/nytka-app/server) или [xinnan-tech/xiaozhi-esp32-server](https://github.com/xinnan-tech/xiaozhi-esp32-server) | Apache-2.0 / MIT |
| VAD и звукообработка | ESP-SR (Espressif, родное для ESP32-P4) | MIT |

## Что меняем (отличия от Omi)

1. **Облако → локальный хаб.** Store-and-forward: кулон работает без интернета, синхронизация по USB-C или Wi-Fi, когда пользователь захочет.
2. **Аппаратная приватность.** Тумблер физически обрывает линию микрофона + светодиод записи — не программное «выключено», а гарантия на уровне платы.
3. **Платформа ESP32-P4** вместо nRF52. P4 тянет VAD + Opus на чипе; уже есть готовая обвязка (питание/батарея/кнопки, интерфейсы USB/Wi-Fi) из проекта TMC.

## Ключевая инженерная задача — автономность

Всегда-включённый микрофон съедает батарею. Решение: Opus-кодирование на чипе + duty-cycle (запись только при обнаружении голоса через VAD) + буфер в PSRAM/SD вместо постоянного радиоканала. BLE (Opus-over-GATT) остаётся запасным каналом и обеспечивает совместимость с клиентами Omi.
